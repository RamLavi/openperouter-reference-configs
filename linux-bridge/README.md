# Linux Bridge 
Reference configurations for connecting KubeVirt VMs to EVPN L2 VNI, using linux-bridge attachments.
- `01-openperouter-underlay.yaml` - OpenPERouter EVPN underlay configs.
- `02-openperouter-vnis.yaml` - OpenPERouter EVPN VNI configs.
- `03-vni-linux-bridge-nad.yaml` - Linux-bridge NetworkAttachmentDefinition.
- `04-workloads.yaml` - Kubevirt VMs example.

>**Note**: Manifests are generated by the described bellow scripts.

# Testing
To test the reference configs, the following scripts can be used:

## `test/env.sh`
The `test/env.sh` control all related parameters, including the underlay
network addresses, VM, and external-network settings.
Change the `test/env.sh` according to your environment.

## `test/setup.sh` 
Automates the described example in repository [README](../README.md), and the following additions:
- Temaplates frr.conf, OpenPERouter configs, variables controled by `test/env.sh`.
  </br>**Note**: The generated files are the reference configs and used by the script.
- `external-router` entrypoint.sh wait for all network attachment before provisioning EVPN network devices.
- `external-router` container is wired to the EVPN underlay network on creation, and connected to the external-network after its up.
- `external-router` is configured as the external-network gateway:
  - `external-router` container is assigned with the `.1` IP address.
  - The external-network IP allocation range is set to the network CIDR second half (..128/25),
    to ensure `.1` is not assinged for any other container.
- Wait for `external-reouter` network attachments before genering perouter configs. 
- Provision macvlan device for the EVPN underlay NIC using iptools.
  </br>**Note**: k8s-nmstate is not used because when OpenPERouter takes ownership of the underlay NIC (e.g.: the macvlan device),
  it moves it to OpenPERouter network-namespace. k8s-nmstate reconciles this state and re-creates the macvlan device,
  resulting in BGP connectivity issues.
 
## `test/test.sh` 
- Temaplates VMs, SSH key secret, Linux-bridge NAD, variables controled by `test/env.sh`.
  </br>**Note**: The generated files are the reference configs and used by the script.
- Tests bidirectional connectivity between Kubevirt VMs and external-network over EVPN L2 VNI, using linux-bridge attachment.
- The script support `--restart-vms` flag, when set it restart the VMs. Useful for applying related changes.
- Test results are written to `test/test-result-summary.txt`
- Notable VM settings: 
  - SSH key secret is created and mounted to the VM. SSH key path and other settings controled by `test/env.sh`. 
    The VMs are connected to the default cluster-network to allow SSH to VMs using `virtctl ssh`, as it realy on cluster API.
    </br>**Note**: `virtctl console` is almost imposible to use for automation. SSH is much easier to work with.
  - Static IP addresses are set using cloud-init for the EVPN underlay NIC.
  - Static route for external-network inbound traffic (src 192.169.1.0/24) toward EVPN underlay NIC (e.g.: via GW 192.170.1.1).
  - </br>**Note**: The route is crucial for enable external-client to reach the VM, otherwise ICMP replay packets routed to 
    the winning default route result in connectivity issues.

## `test/cleanup.sh` 
Remove the described above entities.

## Debugging 
`results/gen-router-reports.sh` generate networking and routing state info report for the cluster worker nodes (hosting the VMs),
external-router, and external-client.
Gereated reports can be found at `results/`

### Example
Initial run:
```bash 
$ ./test/setup.sh  && ./test/test.sh && ./results/gen-router-reports.sh 
```
Re-run test after VM / NAD change: 
```bash 
$ ./test/test.sh --restart-vms 
```
Start fresh:
```bash 
$ ./test/cleanup.sh && ./test/setup.sh  && ./test/test.sh && ./results/gen-router-reports.sh 
```
